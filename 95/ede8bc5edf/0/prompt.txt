# Backend-Handbuch aus DB mit Volltextsuche

## Summary
- Das statische `docs/backend-handbuch/index.html` wird durch ein geschütztes Backend-Handbuch unter `/backend/handbook` ersetzt.
- Inhalt bleibt versionierte Repo-Quelle, wird aber in DB-Abschnitte synchronisiert und aus der DB gerendert.
- Zugriff erhalten alle eingeloggten Rollen: Admin, Editor und Blogger.
- Screenshots entfallen; stattdessen bekommt jeder relevante Abschnitt direkte Links zu Backend-/Frontend-Seiten.
- `AGENTS.md` wird erweitert: UI-/Code-Änderungen müssen gegen das Handbuch geprüft und bei Bedarf dort ergänzt werden.

## Key Changes
- Neue DB-Tabelle `backend_handbook_sections`:
  - Felder: `slug`, `parent_slug`, `position`, `section_label`, `title`, `summary`, `body_html`, `body_text`, `keywords[]`, `links jsonb`, `source_digest`, `search_vector`.
  - Indexe: unique `slug`, normaler `position`, GIN auf `search_vector`.
  - `search_vector` als PostgreSQL Generated Column mit gewichteter deutscher Volltextsuche: Titel/Keywords stärker, Body schwächer.
- Neue Repo-Quelle, z. B. `app/models/concerns/backend_handbook_defaults.rb`:
  - enthält die aktuellen Handbuchabschnitte als strukturierte Definitionen.
  - übernimmt die bestehenden Inhalte aus `docs/backend-handbuch/index.html`.
  - ersetzt alle Screenshot-Figures durch Linklisten wie `/backend/events`, `/backend/blog`, `/backend/settings/edit?section=meta_connection`, `/`, `/events`, `/search`.
- Synchronisierung:
  - `BackendHandbookSection.sync_defaults!` upsertet alle Definitionen, berechnet `body_text` und entfernt veraltete Slugs.
  - Initiale Migration erstellt Tabelle und synchronisiert den aktuellen Inhalt.
  - `db/seeds.rb` ruft ebenfalls `BackendHandbookSection.sync_defaults!` idempotent auf.
  - Neuer Task `backend_handbook:sync` für manuelle Produktions-/Staging-Synchronisierung.
  - Für spätere Handbuch-Content-Änderungen muss zusätzlich eine kleine Datenmigration den Sync auslösen, damit Production über `db:prepare` aktualisiert wird.

## Backend UI
- Neue Route: `GET /backend/handbook`, Helper `backend_handbook_path`.
- Neuer Controller `Backend::HandbookController`, bewusst nicht von `Backend::BaseController`, weil Blogger sonst ausgeschlossen wären.
  - Zugriff erlaubt, wenn `current_user.blog_access?`.
  - Ohne Query: zeigt TOC und ersten/gewählten Abschnitt.
  - Mit `q`: sucht per `websearch_to_tsquery('german', q)` in `search_vector`, sortiert nach Rank und Position.
- Neue View:
  - kompakte Backend-Seite mit Suchfeld, linkem Inhalts-/Trefferbereich und rechtem Abschnitt.
  - Treffer zeigen Titel, Kurzbeschreibung und markierte Textauszüge.
  - Abschnittslinks werden als kleine „Direkt öffnen“-Buttons gerendert.
  - HTML-Body wird aus DB gerendert, aber auf erlaubte Handbuch-Tags sanitizt: Überschriften, Absätze, Listen, Tabellen, Details/Summary, Code, Links, Hinweisboxen.
- Navigation:
  - In `app/views/layouts/application.html.erb` wird ein kleiner Hilfe-/Handbuch-Icon-Link in `backend_nav_links` ergänzt.
  - Aktiver Zustand über `handbook_nav_active?`.
  - Keine neue externe Icon-Bibliothek; ein kleines lokales Inline-SVG mit `aria-label="Handbuch"` und `title="Handbuch"`.

## Documentation Changes
- `README.md`:
  - Link auf statische HTML-Datei ersetzen durch Hinweis auf `/backend/handbook`.
  - Kurzer Betriebsabschnitt für `mise exec -- bin/rails backend_handbook:sync`.
- `AGENTS.md`:
  - Bei jeder UI-, Backend-, Workflow- oder Codeänderung zuerst im Handbuch suchen, ob das Thema bereits erklärt ist.
  - Wenn ein Verhalten neu, geändert oder ein Edgecase betroffen ist: passende Handbuch-Definition ergänzen.
  - Screenshots im Handbuch nicht neu einführen; stattdessen direkte Backend-/Frontend-Links verwenden.
  - Bei Handbuchänderungen Sync-/Suchtests ausführen.
- Entfernen:
  - `docs/backend-handbuch/index.html`
  - `docs/backend-handbuch/assets/screenshots/*`
  - README-Verweis auf die statische Datei.

  - Volltextsuche findet zentrale Begriffe wie `Event-Reihen`, `Consent-Banner`, `Queue`, `Meta Publishing`, `Venue-Dubletten`.
